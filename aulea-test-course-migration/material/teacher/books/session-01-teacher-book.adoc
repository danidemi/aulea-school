[[PRQ-STRANGLER-FIG-PATTERN]]
== PRQ-STRANGLER-FIG-PATTERN — The strangler-fig migration pattern

*Sequence:* 1 +
*Item type:* lesson +
*Style:* lecture_discussion +
*Delivery pattern:* shared +
*Duration:* 15 min

=== Facilitation notes

This is a root node in DESIGN — nothing is prerequisite to it — and CURRICULUM's own note calls
it "the motivating framing for every DR that follows." `[stated]` Open with the coexistence
problem directly: the legacy system and the new microservices must answer requests side by side
for the whole migration window, not only at a final cutover. `[stated]` Before showing any
diagram, ask the group whether they have lived through a big-bang cutover and how it went — this
is the discussion stop the `lecture_discussion` style calls for. `[inferred]`

=== Key points to land

* The pattern's name comes from the legacy system being progressively "strangled" as traffic
  moves away from it, not replaced in one step, so both environments coexist during the migration
  window. `[stated]`
* This is the framing for every DesiredResult taught in this course; refer back to it whenever a
  DR is introduced. `[inferred]`

=== Common misconceptions to watch for

Learners sometimes assume the legacy system is deleted as soon as one microservice replaces a
piece of it. Correct this before moving to PRQ-SCG-BASICS: the legacy system keeps serving every
path not yet migrated until the migration is complete. `[inferred]`

=== Timing guidance

Budgeted 15 min per CURRICULUM. If the discussion runs long, cut the second discussion prompt
rather than the pattern definition — the definition is required for every later item in this
session, most directly PRQ-PATH-BASED-ROUTING (sequence 8), which DESIGN lists as requiring this
node. `[inferred]`

* A JWT has three parts: header, claims (payload), and signature. `[inferred]`
* "Valid" here means the signature checks out and standard claims (`exp`, `aud`, `iss`) are
  acceptable — this is the pass-1, shallow depth per DESIGN's `depth_staging`. `[stated]`
* Constructing a new JWT (pass 2, deep) is Session 2's PRQ-JWT-FUNDAMENTALS-DEEP — do not teach
  construction here. `[stated]`

may push into token construction today. DESIGN's `depth_staging` explicitly reserves that for pass
2 in Session 2 (PRQ-JWT-FUNDAMENTALS-DEEP); redirect the question there rather than answering it
now. `[inferred]`
