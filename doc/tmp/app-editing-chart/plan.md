## Context (read this before resuming work)

- Origin: `learning-curriculum-architect` stores the DESIGN SSOT graph
  (`design/knowledge_goals_graph.md`) as markdown tables. Humans can't review a graph that way.
  Decision made after discussion in this session: replace the storage format and build a browser
  app to view/edit/certify the graph.
- Full discussion and stack rationale: `doc/tmp/app-editing-chart/01-assessment.md` (the
  consulting exchange that led to these decisions — read it for the *why*, this file is the *what/when*).
- Repo conventions this plan follows (from `CLAUDE.md` and `tools/slides/`):
  - Single Source of Truth per store, one writer, plain text, git-diffable, reviewed by human
    commit — no in-band "approved" flag needed for the graph store (commit = certification).
  - The `tools/slides/` toolchain is the existing pattern to mirror: containerised (Docker),
    invoked via a thin wrapper script, model-is-source / rendered output is a gitignored build
    product, thresholds and schema live in data files not hardcoded in scripts, a linter that
    computes checks nobody hand-verifies.
  - `.claude/reference/ssot_structure.md` is the canonical path table for all SSOT stores — must
    be updated when the DESIGN store's path/format changes.
  - After editing any file under `.claude/agents/` or `.claude/skills/`, run
    `learning-support-agent-coherence` before considering the change final.

### Decisions locked in during the design discussion

| Question | Decision |
|---|---|
| Who runs the app, where | Local, single human, like `tools/slides` — no auth, no multi-user, no hosted backend |
| Storage format | JSON (not markdown, not an embedded graph DB) |
| Git-diffability required | Yes — plain text, pretty-printed, stable ordering |
| Expected graph size | Tens to ~150 nodes per course — no DB, no scale concerns |
| Frontend stack | Free choice — React + TypeScript, React Flow (canvas/editing), Dagre (auto-layout), React Hook Form + Zod (property panel forms) |
| Backend | Thin local file server only (read/validate/write the JSON file), localhost-bound, no database |
| Canvas positions | NOT part of the SSOT JSON (would pollute diffs with non-semantic changes). Open question below. |
| Certification | A git commit of the JSON file *is* the certification — no in-file status field planned |
| Do we want node positions to persist across editing sessions (sidecar file, e.g. `design/knowledge_goals_graph.layout.json`, not part of reviewed SSOT) or is re-running Dagre auto-layout on every load acceptable? | re-running Dagre auto-layout on every load is acceptable |
| Exact file/schema name and location for the JSON Schema | `.claude/reference/knowledge_goals_graph.schema.json` |
| Does `design/knowledge_goals_graph.md` (existing 85-line example, currently in the repo) get hand-converted to JSON once, or regenerated by re-running the architect agent against a JSON-writing version of its instructions? Affects step 4. | the agent will be rewritten in order to produce the chart in json format instead of current md format. |

## Steps

1. `[x]` **Write the JSON Schema** for the DESIGN store, encoding the node/edge shape currently
   described in prose in `.claude/agents/learning-curriculum-architect.md` (node types
   `Baseline`/`Prerequisite`/`DesiredResult`, id prefixes `BSL-`/`PRQ-`/`DR-`, `provenance_tags`
   and `knowledge_type` enums, `audience`/`skippable_by`/`persona_variant`, `root`/`root_rationale`,
   `depth_staging`, and `Requires` edges with a `reason`). Single schema, saved to
   `.claude/reference/knowledge_goals_graph.schema.json`. `personas` is a flat array of persona id
   strings (not persona definitions — those stay in the markdown STUDENT_PERSONAS SSOT, which this
   schema doesn't reference).

2. `[x]` **Update `.claude/agents/learning-curriculum-architect.md`** so it writes
   `design/knowledge_goals_graph.json` per the new schema instead of markdown tables. Keep the
   conceptual model (roles, strategy, closure check, deliberate roots, per-persona applicability)
   as-is — only the *serialization* changes.

3. `[x]` **Update `.claude/reference/ssot_structure.md`** — DESIGN store path
   `design/knowledge_goals_graph.md` → `design/knowledge_goals_graph.json`.

4. `[x]` **Migrate the existing example graph** at `design/knowledge_goals_graph.md` to the new
   JSON format (resolve the open question above first: hand-convert vs regenerate).

5. `[x]` **Scaffold the app** under `tools/graph/`:
   - Vite + React + TypeScript project.
   - React Flow canvas with custom node components colour-coded by node type, custom edge
     rendering showing the `reason` label.
   - Dagre auto-layout run on graph load (resolve the layout-persistence open question first).
   - Side panel: React Hook Form + Zod, form fields mirroring the JSON Schema enums, so invalid
     values are caught before save, not after.

6. `[x]` **Local file server**: minimal Node/Express process bound to `localhost` only. Endpoints:
   read the JSON file, validate + write it back on save. No auth, no database.

7. `[x]` **`check` command**: schema validation + the closure check (every node has an incoming
   edge or is a `Baseline`/`root: true`) as a standalone script, mirroring `tools/slides/slidelint.py`'s
   "linter computes it, nobody hand-verifies" philosophy.

8. `[x]` **Dockerfile + wrapper script** `tools/graph/graph` with subcommands `edit <file>` (start
   server, open browser) and `check <file>` (run step 7 headless) — same invocation shape as
   `tools/slides/slides`.

9. `[x]` **Smoke test** against the migrated example graph (step 4): open it, confirm layout is
   readable, add/remove/edit a node and edge, save, confirm the git diff is small and readable,
   confirm `check` passes.

10. `[x]` **Documentation**: short reference doc for the JSON model (mirroring
    `.claude/reference/slide_model_spec.md`'s role for slides) plus a `tools/graph/README.md`
    covering install/run, analogous to how `tools/slides/` is documented in `CLAUDE.md`.

11. `[x]` **Run `learning-support-agent-coherence`** after steps 2–3 land, before considering the
    agent-side change final — it audits exactly this kind of name/path drift.
